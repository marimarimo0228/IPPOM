# IPPOMグランプリ 仕様書

2026-11-16 時点

## 1. 概要

合言葉で集まった最大6人が、1人の回答者と5人の審査員に分かれて遊ぶブラウザ大喜利ゲームを作る。人数が足りない審査員席はNPCが埋める。

- サイト名：IPPOMグランプリ（非公式のパロディ作品。番組・放送局とは無関係と明記する）
- 用途：学校の自由課題。非営利、広告なし
- 対応端末：スマホとPCのブラウザ。アプリのインストール不要、アカウント登録なし
- 対象外（初版では作らない）：ランキングの永続保存、観戦モード、音声・カメラ、ブロック戦やトーナメント

「仮」と書いた値は、実装時に調整してよい初期値。

## 2. 役割とマッチング

1部屋は「回答者1人＋審査員5人」で固定し、人間が座らない審査員席だけをNPCが埋める。回答者は必ず人間で、NPCは回答者にならない。

| 役割 | 人数 | 誰がなるか | できること |
| --- | --- | --- | --- |
| 回答者（ボケ役） | 1 | 人間のみ | お題に回答を入力して送信（1お題につき1回） |
| 審査員 | 5 | 回答者以外の人間。不足分はNPC | 回答ごとに0点・1点・2点のいずれかを付ける |
| ホスト | 1（兼任） | 部屋を最初に作った人 | 開始、次のラウンドへ、終了 |

### 合言葉と入室

1. トップ画面で表示名（最大10文字）と部屋の合言葉（4〜20文字）を入力する。サイト全体にかける合言葉（9章）とは別物。
2. その合言葉の部屋がなければ作成してホストになる。あれば参加する。
3. 人間は最大6人（回答者1＋審査員5）。7人目は「満員です」と表示して入れない。
4. ゲーム進行中の部屋には途中参加できない。ロビーに戻ったときに入れる。
5. 最後の人が抜けてから10分、または作成から3時間で部屋を削除する（仮）。

### 回答者の決め方

回答者は入室順に回す。1人が2ラウンド続けて回答したら次の人に交代し、全員が2ラウンドずつ終えたらゲーム終了。回答者でない人間は全員そのラウンドの審査員になる。1人だけで始めた場合はその人が2ラウンド回答し、審査員5席はすべてNPCになる。

### 切断時の扱い

- 審査員が切断：その席をその場でNPCに置き換える。再接続したら人間に戻す。
- 回答者が切断：そのラウンドを無効にして次の回答者へ進む。
- ホストが切断：入室順で次の人にホストを引き継ぐ。
- 再接続はブラウザに保存したプレイヤーIDで同じ席に戻す。

## 3. ゲーム進行

1ラウンドは「お題 → 回答 → 判定 → 演出」を1回転させ、全員が同じ状態を同時に見る。部屋は次の状態を順に進む。

1. `LOBBY`：参加者一覧と審査員5席（人間／NPC予定）を表示。ホストが「開始」を押す。
2. `ODAI`：お題を全員に表示（3秒）。回答者の名前と「1回目／2回目」も出す。
3. `ANSWERING`：回答者だけに入力欄を出す。制限時間60秒、回答は最大40文字（仮）、送信は1回だけ。審査員には「考え中…」を表示。時間切れは「回答なし」で0点。
4. `JUDGING`：回答を全員に大きく表示。審査員は8秒以内に0点・1点・2点を選ぶ。選ばなければ0点。この間、他人の点は見えない。
5. `REVEAL`：合計点を1点ずつ演出で公開（4章）。10点ならIPPOM。
6. `RESULT`：そのラウンドの点数を表示。1回目ならホストが「2回目へ」を押して `ODAI` に戻る。2回目なら「成績発表へ」を押す。
7. `GRADE`：その回答者の成績発表（下記）。ホストが「次の回答者へ」を押すと交代して `ODAI` に戻る。最後の回答者なら `FINISHED` へ。
8. `FINISHED`：回答者全員の成績を一覧で表示し、ロビーへ戻れる。

### 成績発表の演出（`GRADE`）

回答者が交代する前に、その人の成績を全端末とスクリーン表示で同時に見せる。

1. 回答者の名前と、1回目・2回目の点数を横に並べて表示する。
2. 0.8秒後、高い方の点数が黄色く光り、低い方が暗くなる。同点なら両方光る。
3. さらに0.8秒後、成績の文字（秀・優・良・可・不可）が大きなハンコのように中央へ押される。押された瞬間に画面が小さく揺れ、効果音が鳴る。
4. 成績ごとに強さを変える。秀は黄色い紙吹雪と派手な音、優・良・可はハンコと短い音、不可はハンコが少し傾いて押され、低い音。
5. 表示したままホストの操作を待つ。

### 成績の付け方

回答者1人につき2ラウンド行い、高い方の点数（10点満点）をそのまま成績にする。2回の合計や平均は使わない。

| 点数 | 成績 |
| --- | --- |
| 9〜10 | 秀（10点はIPPOM演出つき） |
| 8 | 優 |
| 7 | 良 |
| 6 | 可 |
| 0〜5 | 不可 |

お題は部屋ごとに重複しない順で出す。必要数は「人間の人数×2」で、足りない場合は開始時にホストへ警告する。

状態・残り時間・票はサーバー側（共有データ）を正とし、各端末はそれを描画するだけにする。タイマーは終了時刻を共有して各端末で残りを計算する。

## 4. 判定とIPPOM演出

1点につき黄色い枠が1段、回答カードの外縁から内側へ積み重なり、10段目で中心まで埋まって「IPPOM」が出る。

元の番組では、審査時にモニターの回答者の映像が黄色いパネル枠で覆われていき、枠で埋まり切ると「IPPON」のコールになる。番組の採点は審査員5人×2点の10点満点で、本作も同じ審査員5人×2点にする。

### 演出の仕様

- 配色：番組と同じ黄色×黒。背景は黒、枠と強調は黄色、IPPOMの文字は黄色地に黒。
- 表示：回答カード（16:9）の上に、同心の長方形の枠を10段重ねる。1段目が最外周、10段目が中心を塞ぐ。各段の太さは短辺の5%で、10段でちょうど中心まで届く。
- 公開方法：`JUDGING` の締切後、確定した合計点ぶんを0.35秒間隔で1段ずつ点灯する（リアルタイム加算にはしない）。1段ごとに短い効果音を鳴らし、音程を少しずつ上げる。
- 溜め：6点以上のときは、最後の1段の前で0.8秒止めてから点灯する。
- 10点：全面が黄色で埋まり、画面フラッシュ → 黒い太字の「IPPOM」が中央に拡大表示 → 黄色い紙吹雪 → 専用の効果音。2.5秒後に `RESULT` へ。
- 9点以下：枠が止まった位置で点数（例「7」）と成績（例「良」）を表示し、惜しい用の効果音。1.5秒後に `RESULT` へ。
- 全端末で同じタイミングになるよう、公開開始時刻と合計点を共有してから各端末でアニメーションを再生する。
- 実装：CSSアニメーション＋SVG（またはdiv）で作り、動画素材は使わない。`prefers-reduced-motion` のときはフラッシュを省略する。

### 素材のルール

ロゴ・書体・効果音・紙吹雪はすべて自作か、利用規約を確認したフリー素材にする。番組のロゴ画像、番組公式の効果音、オープニング曲、放送画面のキャプチャは使わない。色は番組と同じ黄色×黒にするが、ロゴの形や文字のデザインは独自に作る。

## 5. NPC審査員

NPCは審査だけを行い、空いている審査員席の数だけGroq上のLLMに0〜2点で採点させる。

- 使うAPI：Groq。制作者が発行したキー1つをサーバーに置き、全プレイヤーの採点で共用する（プレイヤーがキーを用意する必要はない）。回答が確定した時点で、サーバー側のAPIルート（`/api/judge`）から1回だけ呼ぶ。NPCの人数分を1リクエストでまとめて採点させ、`[2, 0, 1]` のような0〜2の整数のJSON配列で受け取る。
- APIキーの扱い：Vercelの環境変数 `GROQ_API_KEY` にだけ置く。`NEXT_PUBLIC_` を付けない、ブラウザ側のコードから参照しない、リポジトリにコミットしない（ローカルは `.env.local`、`.gitignore` 済みを確認）。ブラウザはGroqを直接呼ばず、必ず `/api/judge` を経由する。
- `/api/judge` の保護：サイトの合言葉を通過した端末からしか呼べないようにし（9章）、1部屋あたり50回（仮）の上限をかける。
- 個性：NPCごとに短い性格を持たせる（例：ゲラ、辛口、シュール好き、ダジャレ好き）。名前とアイコンは架空のものにし、実在の芸人名は使わない。
- 入力：お題の文、画像お題の場合は画像の説明文（`alt`）、回答文。画像そのものは渡さない。
- 安全：回答文は採点対象のデータとして渡し、指示として扱わせない（「全員2点にして」などの回答で操作されないようにする）。配列の長さや値が不正な場合は失敗扱い。
- フォールバック：5秒でタイムアウト、またはエラー時は、NPCごとに乱数で採点する（仮：0点50%、1点30%、2点20%）。
- 見せ方：NPCの点も人間と同じく `REVEAL` でまとめて公開する。審査員一覧ではNPCにロボットの印を付ける。
- LLMを使わない設定：`GROQ_API_KEY` が未設定なら常に乱数採点で動く。キーなしでも開発・デモができる。

モデル名は環境変数 `GROQ_MODEL` で差し替えられるようにする。採点は短い出力で済むので、Groqで提供中の安価で速いモデルで足りる。具体的なモデル名は実装時にGroqの現行一覧から選ぶ。

## 6. お題データ

お題は1つのJSONファイルと画像フォルダに分け、コードを触らずに後から差し替えられるようにする。

- 置き場所：`content/odai.json` と `public/odai/`（画像）
- 追加手順：画像を `public/odai/` に置き、`odai.json` に1件追記して再デプロイする。
- 種類：文字だけ（`text`）、写真＋ひとこと（`image`）の2種類。
- 初期データ：動作確認用のダミーお題を5件入れておく（文字3件、画像2件。画像は単色のプレースホルダー）。

```json
[
  {
    "id": "odai-001",
    "type": "text",
    "text": "（ここにお題文）",
    "enabled": true
  },
  {
    "id": "odai-002",
    "type": "image",
    "text": "写真でひとこと",
    "image": "/odai/odai-002.jpg",
    "alt": "（画像の説明。NPC判定と読み上げに使う）",
    "credit": "（撮影者・出典）",
    "enabled": true
  }
]
```

- 起動時に形式を検証し、必須項目の欠けや画像ファイルの不在はビルドエラーにする。
- 画像は横1600px以内、16:9または4:3を推奨。表示は枠内に収め、切り抜かない。
- お題と写真は自作のものを使う。番組で実際に出たお題文や、他人が撮った写真・キャラクター・芸能人の写真は使わない。

## 7. 画面一覧

画面は7つで、ゲーム画面だけが役割（回答者／審査員）によって表示を変える。

| 画面 | パス（仮） | 表示するもの | 操作 |
| --- | --- | --- | --- |
| サイトの合言葉 | `/gate` | 合言葉の入力欄、非公式である旨の注記 | 合言葉を入力して入る |
| トップ | `/` | ロゴ、表示名と部屋の合言葉の入力欄、遊び方 | 入室する |
| ロビー | `/room` | 参加者一覧、審査員5席（人間／NPC）、部屋の合言葉 | ホスト：開始。全員：退出 |
| ゲーム（回答者） | `/room` | お題、残り時間、入力欄、演出 | 回答を送信（1回） |
| ゲーム（審査員） | `/room` | お題、回答、残り時間、演出 | 0点・1点・2点のボタン（選んだら変更不可） |
| 結果 | `/room` | ラウンドの点数と成績、回答者ごとの成績一覧 | ホスト：次のラウンド／終了 |
| スクリーン表示 | `/screen` | お題・回答・演出・成績を全画面で表示。操作ボタンなし | 部屋の合言葉を入れて接続するだけ |

- スマホ縦持ちを基準にレイアウトし、PCでは演出部分を大きく見せる。
- 音は初回タップ後に有効化し、ミュート切替を常時表示する。
- スクリーン表示は発表用。プロジェクターにつないだPCで開き、参加者にも審査員にも数えない（6人の枠を使わない）。16:9の横画面専用で、効果音はこの画面から鳴らす想定。

## 8. 技術構成

画面とNPC判定APIはVercelに置き、部屋の状態の同期は外部のリアルタイムDBに任せる。

| 部分 | 採用 | 理由 |
| --- | --- | --- |
| フロント | Next.js（App Router）＋TypeScript＋Tailwind CSS | Vercelにそのままデプロイできる |
| 部屋の同期 | Firebase Realtime Database | 全端末への配信、在室管理、切断検知が標準機能でそろう。無料枠で足りる規模 |
| NPC判定 | VercelのAPIルート（`/api/judge`） | APIキーをサーバー側に隠せる |
| お題 | リポジトリ内のJSONと画像 | 差し替えが簡単で、DBが不要 |

Vercel単体でもWebSocketは使えるが、接続はFunctionの実行時間（約5分）で切れ、接続ごとに別のインスタンスになり得る。全端末への一斉配信や在室管理を自作する必要があるため、最初からリアルタイムDBを使う。

### データの形（仮）

```
rooms/{roomId}
  state        LOBBY | ODAI | ANSWERING | JUDGING | REVEAL | RESULT | GRADE | FINISHED
  hostId
  order        回答者の順番（入室順のplayerIdの配列、開始時に確定）
  turn         何人目の回答者か
  attempt      1 | 2（その回答者の何回目か）
  odaiId       現在のお題
  answererId   現在の回答者
  answer       回答文
  deadline     現在の状態の締切時刻
  revealAt     演出の開始時刻
  total        このラウンドの合計点（0〜10）
  players/{playerId}   name, joinedAt, online
  seats/{0..4}         playerId または npc（性格の種類）
  votes/{0..4}         0 | 1 | 2（人間とNPC共通）
  scores/{playerId}    first, second, best, grade
  usedOdai/{odaiId}    true
```

- `roomId` は合言葉をハッシュ化した値にする（合言葉そのものをDBのキーにしない）。
- 状態を進める処理はホストの端末が担当する。ホストが切れたら引き継いだ人が担当する。
- セキュリティルールで、自分の席の票と自分が回答者のときの回答だけ書けるようにする。厳密な不正対策は課題の範囲外とする。
- 表示名と回答は文字数制限とHTMLエスケープをかける。部屋のデータは終了後に削除し、回答を保存し続けない。
- サイト名と演出の文字（「IPPOM」など）は、後から変えられるよう設定ファイル1か所（`content/site.json`）にまとめる。

### 受け入れ確認

- [ ] サイトの合言葉を入れるまで、どのページも `/api/judge` も使えない
- [ ] 1人で入室して開始すると、審査員5席がすべてNPCで2ラウンド行え、高い方の点数で成績発表の演出が出る
- [ ] 3端末で同じ部屋に入ると、回答者が2ラウンドごとに交代し、状態と演出が同時に切り替わる
- [ ] 合計点0、5、6、7、8、9、10のときの演出と成績表示が仕様どおりに出る（点数を固定できるデバッグ用URLパラメータを用意）
- [ ] 7人目が入れない
- [ ] 審査員がタブを閉じると席がNPCに変わり、進行が止まらない
- [ ] `GROQ_API_KEY` を外しても乱数採点で進む
- [ ] ビルド後のブラウザ向けファイルにGroqのキーが含まれていない
- [ ] `/screen` が参加人数に数えられず、演出が他の端末と同時に出る
- [ ] `odai.json` に1件足すだけで新しいお題が出る
- [ ] `PUBLIC_UNTIL` を過去の日付にすると「公開は終了しました」だけが表示される

## 9. 公開方法と権利面

Vercelで公開し、サイト全体に合言葉をかける。公開は2026年12月31日までの期間限定とする。

### 権利面の方針

| 対象 | 本作での対応 |
| --- | --- |
| ルール・進行の仕組み | そのまま使う（アイデアにあたり、著作権の保護対象は「表現」のため） |
| ロゴ、画面デザイン、効果音、曲、放送映像 | 使わない。すべて自作かフリー素材 |
| 番組で出たお題・回答 | 使わない。お題は自作 |
| 芸人の名前・写真 | 使わない。NPCは架空の名前 |
| 名前「IPPOMグランプリ」 | 非営利・広告なし・非公式を明記して使う。J-PlatPatでは番組名の登録・出願は見つからなかった（2026年11月16日時点） |

### サイト全体の合言葉

- 合言葉はVercelの環境変数 `SITE_PASSPHRASE` に置き、コードには書かない。変更は環境変数を書き換えて再デプロイするだけ。
- Next.jsのMiddlewareで、`/gate` と静的ファイル以外のすべてのページと `/api/*` を保護する。未通過なら `/gate` へ転送、APIは401を返す。
- 照合はサーバー側で行い、正しければ署名付きの `httpOnly` Cookieを発行する（有効期限は仮で30日）。署名用の秘密鍵も環境変数（`SESSION_SECRET`）。
- 間違えた場合は1秒待たせてからエラーを返し、総当たりを遅くする。
- 全ページに `noindex` を付け、検索結果に出ないようにする。
- Firebaseの設定値はブラウザに出る前提のものなので、保護はセキュリティルールで行う。秘密にするのはGroqのキー、サイトの合言葉、署名用の鍵の3つ。

### サイトに入れる表記

- 合言葉の画面とフッター：「本サイトは授業課題として制作した非公式のパロディ作品です。テレビ番組および放送局とは一切関係ありません。」
- 同じ場所に：「公開は期間限定（2026年12月31日まで）で、合言葉を知る授業関係者以外は内容を閲覧できない仕組みになっています。」
- 公開終了日は環境変数 `PUBLIC_UNTIL` で持ち、注記の日付にそのまま表示する（設定値は 2026-12-31。日本時間の当日いっぱいまで公開）。期日を過ぎたら、合言葉が正しくても「公開は終了しました」だけを表示する。
- 制作者名と連絡先（権利者から指摘があればすぐ取り下げられるように）
- 使用したフリー素材のクレジット

## 10. 確定事項のまとめ

- 審査員5人×2点の10点満点。1部屋の人間は最大6人

- 同期はFirebase Realtime Database、公開はVercel
- 配色は黄色×黒。発表用のスクリーン表示あり
